# 2026-06-04 — CropMLP on two new ViT-Tiny DINO backbones

## Goal

Two new ViT-Tiny DINO backbones were trained earlier in May 2026 as a
parameter-controlled comparison against the production ViT-Small backbone
that powers `results_crop_mlp/`. Today's job: train a CropMLP on top of
each new backbone using *exactly the same method* as the ViT-Small run, so
the three sets of results can be compared directly.

The two new backbones differ only in the per-experiment crop cap used
during DINO pretraining:

- `checkpoints/dino_vit_tiny/dino/best_backbone.pt` — 5,000 crops/exp cap
- `checkpoints/dino_vit_tiny_10k/dino/best_backbone.pt` — 10,000 crops/exp cap

## Methods

### Backbones (already trained before today)

All three backbones use `ViTSmall` from `models/backbone.py` (a generic
ViT — name is historical). Configuration:

| Field | ViT-Small v1 | ViT-Tiny 5K | ViT-Tiny 10K |
| --- | --- | --- | --- |
| `embed_dim` | 384 | 192 | 192 |
| `num_heads` | 6 | 3 | 3 |
| `depth` | 12 | 12 | 12 |
| `patch_size` | 16 | 16 | 16 |
| `img_size` | 128 | 128 | 128 |
| `mlp_ratio` | 4.0 | 4.0 | 4.0 |
| `drop_path_rate` | 0.1 | 0.1 | 0.1 |
| `time_conditioned` | False | False | False |
| Backbone parameters | **21,418,368** | **5,400,768** | **5,400,768** |

The Tiny variants were trained from scratch by
`train_vit_tiny_scratch.py`, forked from `train_dino_correctly.py` (the
ViT-Small reproduction). Every non-architectural setting — DINO head
(2048 → 256 bottleneck → 4096 prototypes, 3 layers), optimiser (AdamW
lr=5e-4 → 1e-6, wd 0.04 → 0.4, batch 64, 100 epochs, warmup 10), teacher
EMA (0.996 → 1.0), temperatures (teacher 0.04 → 0.07 over 30 epochs,
student 0.1), multi-crop (2 global + 6 local @ 64×64, scales (0.7,1.0)
and (0.3,0.6)), CLAHE normalisation (mean 0.3387, std 0.1173),
reduced-magnitude augmentation (`aug_brightness=0.03`), and reflection
padding (`cv2.BORDER_REFLECT_101`) — was held identical to the production
v1 run.

Outcomes:
- ViT-Small v1: best epoch 43, loss 0.815, ~207K training crops
- ViT-Tiny 5K: best epoch 32, loss 0.989, 261,732 training crops
- ViT-Tiny 10K: best epoch 27, loss 0.926, 516,732 training crops

### Feature extraction (today)

For each Tiny variant, per-crop features were extracted by
`scripts/extract_features_tiny.py` (new wrapper, ~80 lines), which calls
the existing `training/extract_features.py:extract_all_features()` with
the Tiny-specific arguments (`embed_dim=192, num_heads=3, img_size=128,
time_conditioned=False`).

Inputs:
- 53 preprocessed HDF5 files in `preprocessed/` (focused-class crops at
  128×128, CLAHE-normalised on the fly)

Outputs:
- `features_tiny_5k/<exp>.npz` — 53 files, ~1.1 GB total
- `features_tiny_10k/<exp>.npz` — 53 files, ~1.1 GB total

Each `.npz` holds `features` (float16, shape `(N, 192)`) and `timestamps`
(float64, absolute Unix ms). Extraction took ~45 min per variant on the
shared RTX 3090.

### CropMLP training (today)

Driver: `scripts/strain_holdout_crop_classifier.py` (existing — one
2-line patch today to make `evaluate_fold` infer `in_dim` from the saved
state-dict, so 192-dim Tiny checkpoints don't crash the existing 384-dim
default).

Architecture: `Linear(D → 128) → LayerNorm → GELU → Dropout(0.3) →
Linear(128 → 64) → LayerNorm → GELU → Dropout(0.3) → Linear(64 → 2)`,
where `D = 192` for Tiny and `D = 384` for v1 (58,050 vs 33,474 params).

Training method (identical to the v1 `results_crop_mlp/` run, and the
same on both Tiny variants):

- Train filter: only crops with `rel_ts ≥ 2400 s` (≥ 40 min exposure),
  capped at 10,000 per experiment.
- Optimiser: AdamW lr=1e-3, weight_decay=0.01, batch=2048 train / 4096
  val, grad-clip 1.0.
- Schedule: 5-epoch warmup + cosine to 1% of base lr; 100 epochs max;
  early-stop on val AUROC with patience 15.
- Loss: cross-entropy with class weights `len(y) / (2 · n_per_class)`.
- 5-fold strain-holdout CV (seed 42): each fold holds out 2 R-strains +
  2 S-strains; one experiment per remaining strain goes to val, the
  rest to train. Folds are byte-identical across all three runs because
  the seed and the set of EC strains in the features dir are identical.

Held-out strains per fold (same for all three runs):

| Fold | R | S | n_test |
| ---: | --- | --- | ---: |
| 0 | EC58, EC87 | EC36, EC39 | 12 |
| 1 | EC58, EC60 | EC33, EC39 | 11 |
| 2 | EC35, EC87 | EC33, EC39 | 11 |
| 3 | EC35, EC87 | EC36, EC39 | 12 |
| 4 | EC40, EC48 | EC39, EC67 | 11 |

Evaluation: the trained MLP is run over *all* crops of each held-out
experiment (no min-time filter), with predictions binned per 5-minute
window for time-series plots, and a single per-experiment prediction
computed as `mean(P(R))` thresholded at 0.5.

## Interpretation

1. **AUROC is invariant** across a 4× backbone shrink (21.4M → 5.4M). All
   three feature spaces induce the *same ranking* of the 10–12 held-out
   experiments by per-experiment mean P(R) on every fold.

2. **Accuracy is also invariant** between v1 and Tiny-5K, and degrades by
   exactly one held-out experiment for Tiny-10K (in fold 2: 5/11 → 4/11).
   AUROC for that fold is unchanged at 0.5333 — the underlying ranking
   is the same, but the decision boundary crosses between two
   experiments differently.

3. **Fold 2 (EC35 + EC87 vs EC33 + EC39) is intrinsically hard.** All
   three backbones produce AUROC 0.5333 there. This is a strain-pairing
   issue, not a representation issue.

4. **More DINO pretraining crops (10K cap) did not help downstream.** The
   DINO best loss did improve (0.989 → 0.926), but the crops appear to
   already be saturated for the downstream R/S task at the 5K cap. There
   is no evidence the smaller backbone needs more pretraining data on
   this dataset.

5. **The ViT-Tiny backbone matches ViT-Small at ~25% the parameters.**
   For a frozen-features pipeline this directly translates into ~4×
   cheaper inference per crop, with no measurable AUROC loss.
